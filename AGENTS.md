## Project

The Backstage app, image, chart, templates and custom plugins for Skylab. Nothing in the catalog is registered by hand: discovery finds repos, and a CI-generated root Location finds templates. See `plan.md` for the full rework plan.

**Current state (2026-10-15):** fresh scaffold at `app/` from `@backstage/create-app` (yarn Berry 4.x, Node 22/24, `packages/app` + `packages/backend`, example org / entities / template still in place). No plugins, Dockerfile CI, chart wrapper, catalog, templates, or Gitea / MCP wiring yet. Local dev requires `brew install node@22` (Node 26 is unsupported) and `yarn install` inside `app/`.

Legacy content: `tetris-react/`, `infra-templates/`, `workload-templates/` predate the rework and are migration source material.

## Layer

**Front door (Backstage).** Owns catalog, templates, and MCP actions for AI clients. Never writes directly to clusters — scaffolder opens PRs instead.

## Workflow

- `main` is protected: branch and open a PR (self-merge, 0 approvals).
- No `Co-Authored-By` trailers in commit messages.
- Templates skip `catalog:register`; discovery picks up new repos on a schedule.

## Target repo shape

```
app/        # Backstage source, new backend system
plugins/
  scaffolder-backend-module-gitea-pr/  # custom gitea:pull-request action
  skylab-actions/                      # platform MCP actions
chart/      # wrapper chart, published to OCI
catalog/    # org.yaml, systems, domains
templates/  # one folder per template
catalog-info.yaml  # root Location, generated by CI
```

## Key decisions

**No manual registration.** `catalog.locations` points at a CI-generated `catalog-info.yaml` whose targets list every template. CI fails if the file drifts from the `templates/` tree, so adding a template means adding a folder.

**Gitea for tenants.** Scaffolder uses the upstream `publish:gitea` action plus a custom `gitea:pull-request` backend module to open PRs against `platform/tenants`. Gitea is also the OIDC provider for Backstage, Argo CD and Grafana.

**MCP for AI clients.** `@backstage/plugin-mcp-actions-backend` exposes catalog + scaffolder endpoints; custom actions in `skylab-actions` surface KubeVela workflow status, Argo sync failures, SLO burn rate, and environment requests. Each action enforces Backstage permissions itself.
