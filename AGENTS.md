## Project

The Backstage app, image, chart, templates and custom plugins for Skylab. Nothing in the catalog is registered by hand: discovery finds repos, and a CI-generated root Location finds templates. See `plan.md` for the full rework plan.

**Current state (2026-10-16):** scaffold at `app/` from `@backstage/create-app` (yarn Berry 4.x, Node 22/24, `packages/app` + `packages/backend`). Image CI (`.github/workflows/image.yml`) builds + Trivy-scans (CRITICAL-only via `.trivyignore`; HIGHs are upstream Backstage transitives tracked via Dependabot), and on `main` pushes signed images to `ghcr.io/<owner>/skylab-backstage` with SBOM + provenance. Custom plugin at `app/plugins/scaffolder-backend-module-gitea-pr/` exposes the `gitea:pull-request` scaffolder action (clone → new branch → copy workspace → commit → push → open PR); registered in `app/packages/backend/src/index.ts`, credentials via `integrations.gitea[].username|password` (Backstage's `GiteaIntegrationConfig` has no `token` field — Gitea PAT goes in `password`). Catalog bootstrapped at `app/catalog/` (Group `platform`, User `skylar`, four Domains, five Systems covering the sibling repos); root `catalog-info.yaml` is the Component for this repo. Entity validator runs in `.github/workflows/catalog.yml` via Roadie's action in a per-file matrix. Dockerfile copies `catalog-info.yaml` + `catalog/` into the image. Gitea entity-discovery (`catalog-backend-module-gitea`) pulls `catalog-info.yaml` from the `platform` Gitea org on a 10-minute schedule; generic OIDC auth provider wired to use Gitea as IdP (`preferredUsernameMatchingUserEntityName` resolver) — frontend sign-in UI still defaults to guest. Kubernetes plugin registered on both sides, pointed at a `homelab` cluster via env vars with KubeVela + Crossplane custom resources listed so entity pages surface Applications / ComponentDefinitions / TraitDefinitions / XRDs / Providers alongside the standard workloads. Argo CD plugin (Roadie's `@roadiehq/backstage-plugin-argo-cd` + `-backend`) wired the same way, one `homelab` instance under `argocd.appLocatorMethods`, authed via `ARGOCD_USERNAME` / `ARGOCD_PASSWORD`; entity pages pick up Argo apps via the `argocd/app-selector` annotation on each Component. Grafana plugin (community, frontend-only) talks to Grafana through a `/grafana/api` proxy endpoint parameterized on `GRAFANA_URL` + `GRAFANA_TOKEN`; `grafana.domain` + `grafana/dashboard-selector` / `grafana/alert-label-selector` annotations surface each Component's dashboards + alerts. Frontend OIDC sign-in UI: `@backstage/plugin-auth` registered in `App.tsx`, `sign-in-page` extension lists `guest` + `oidc` ("Sign in with Gitea"); `app.title` + `organization.name` set to `Skylab`. First golden-path template at `app/templates/go-service/`: Template entity + Go skeleton (OTel-wired `main.go`, distroless Dockerfile, Gitea Actions CI with Trivy + cosign + SBOM, templated catalog + TechDocs) + `tenants-pr/` carrying a one-line KubeVela Application that uses the Skylab `go-service` ComponentDefinition (shipped from `skylab-gitops/charts/kubevela-defs`). Workflow: `fetch:template` → `publish:gitea` (via `scaffolder-backend-module-gitea`, now registered) → `catalog:register` → `fetch:template` → `gitea:pull-request` (custom action). Template is a `type: file` Location in app-config, included in the catalog validator matrix, and copied into the image. Chart wrapper lives in `skylab-gitops/charts/backstage/` at wave 6. Second internal plugin at `app/plugins/skylab-actions/` is a `backend-plugin-module` targeting `mcp-actions` — registers actions on the Backstage `actionsRegistryServiceRef`; first action `platform-ping` is a trivial read-only round-trip for AI-client connectivity. Real actions (SLO burn rate, Argo failures, KubeVela status, env requests) land as follow-ups. Local dev requires `brew install node@22` (Node 26 is unsupported) and `yarn install` inside `app/`.

Legacy content: `tetris-react/`, `infra-templates/`, `workload-templates/` predate the rework and are migration source material.

## Layer

**Front door (Backstage).** Owns catalog, templates, and MCP actions for AI clients. Never writes directly to clusters — scaffolder opens PRs instead.

## Workflow

- `main` is protected: branch and open a PR (self-merge, 0 approvals).
- No `Co-Authored-By` trailers in commit messages.
- Templates skip `catalog:register`; discovery picks up new repos on a schedule.

## Target repo shape

```
app/        # Backstage source, new backend system
plugins/
  scaffolder-backend-module-gitea-pr/  # custom gitea:pull-request action
  skylab-actions/                      # platform MCP actions
chart/      # wrapper chart, published to OCI
catalog/    # org.yaml, systems, domains
templates/  # one folder per template
catalog-info.yaml  # root Location, generated by CI
```

## Key decisions

**No manual registration.** `catalog.locations` points at a CI-generated `catalog-info.yaml` whose targets list every template. CI fails if the file drifts from the `templates/` tree, so adding a template means adding a folder.

**Gitea for tenants.** Scaffolder uses the upstream `publish:gitea` action plus a custom `gitea:pull-request` backend module to open PRs against `platform/tenants`. Gitea is also the OIDC provider for Backstage, Argo CD and Grafana.

**MCP for AI clients.** `@backstage/plugin-mcp-actions-backend` exposes catalog + scaffolder endpoints; custom actions in `skylab-actions` surface KubeVela workflow status, Argo sync failures, SLO burn rate, and environment requests. Each action enforces Backstage permissions itself.

## Cross-repo map
